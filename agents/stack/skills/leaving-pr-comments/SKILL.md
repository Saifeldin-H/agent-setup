# Leaving PR Comments

Lead with the conclusion. Cite the code, check, or behavior that supports it. Say what you verified. Keep the reply short and give a specific next step when one is needed.

Before drafting any GitHub text, read the target repo's `CLAUDE.md`, `AGENTS.md`, and `.claude/rules/*.md` that exist. Omit AI attribution and all AI or model mentions by default. Add attribution or a cross-vendor review block only if the repo rules explicitly allow it and the user or spec asks for it. If attribution is authorized, use the verified public model name and the user's name or GitHub login.

Check the full comment, quotes, and attachments for secrets and private details. Preview the Markdown before posting. Confirm GitHub returned the comment or review URL. Resolve a thread only after confirming the reply was posted and when you have authority to resolve it.
